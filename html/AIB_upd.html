Funcția de actualizare pe sufix

Dacă dorim să actualizam valoarea de pe poziția pos, va trebui să actualizam toate nodurile din AIB care o conțin. Amintim faptul că nodul i conține suma subsecvenței [i - (i&-i) + 1, i] a vectorului, deci prin actualizarea elementului v[pos] vom actualiza de fapt fiecare nod i astfel încât
pos ∈ [i - (i&-i) + 1, i]. Vom demonstra mai târziu în articol că există maxim log2n astfel de noduri, făcând funcția să aibă complexitate de O(log n).

Intrebarea rămâne: cum putem identifica aceste poziții?

Este greu de intuit logic motivul, dar prin aplicarea repetată a operației x = x + (x&-x) începând cu x = pos putem atinge toate nodurile importante. Vom folosi drept reper vizualizarea arborelui indexat binar pentru a deduce formula folosită, dupa care îi vom demonstra validitatea matematic. Iată câteva exemple:

Pentru n = 16 și pos = 3 vom actualiza următoarele noduri:

AIB[3] = v[3] + val;
AIB[4] = v[3] + v[4] + val;
AIB[8] = v[1] + v[2] + v[3] + v[4] + v[5] + v[6] + v[7] + v[8] + val;
AIB[16] = v[1] + v[2] + v[3] + v[4] + v[5] + v[6] + v[7] + v[8] + v[9] + v[10] + v[11] + v[12] + v[13] + v[14] + v[15] + v[16] + val;

Pentru n = 32 și pos = 21 vom actualiza următoarele noduri:

AIB[21] = v[21] + val;
AIB[22] = v[21] + v[22] + val;
AIB[24] = v[21] + v[22] + v[23] + v[24] + val;
AIB[32] = v[1] + v[2] + ... + v[21] + v[22] + ... + v[32] + val;

Pentru n = și pos = vom actualiza AIB[398, 400, 416, 448, 512, 1024].

Reprezentarea grafică a unui AIB

În continuare puteți apăsa pe reprezentarea AIB pe care o preferați:

Reprezentarea clasică

Nodurile arborelui vor avea 2 valori: indexul unic și valoarea propriu-zisă (AIB[index]) pe care o putem ignora când reprezentăm grafic. Când spunem nodul a ne referim la nodul care are indexul egal cu a. Definim astfel arborele de actualizare pe sufix:
Nodul y este părintele nodului x ⇔ y = x + (x&-x) sau y = rădăcina.
*Rădăcina arborelui va fi nodul imaginar n + 1, acesta nu corespunde unei subsecvențe din vector și are doar rolul de a uni mulțimile disjuncte create prin ignorarea nodurilor cu index mai mare decât n.

Observăm că urcând arborele începând cu nodul 3 până la rădăcină parcurgem toate nodurile ce conțin poziția 3 în interval, iar asta este adevarat pentru orice poziție datorită modului în care este definint părintele unui nod oarecare. Așadar, toți indecșii ce conțin poziția pos în interval vor fi termeni ai șirului (x)n, x0 = pos, xi+1 = xi + (xi&-xi), singura precizare fiind că oprim căutarea în momentul în care xi+1 depășește rădăcina (echivalent cu xi+1 ≤ n). Numărul maxim de noduri pe care le vizităm pe drum este în cel mai rău caz log2n, făcând complexitatea funcției O(log n).

Reprezentarea prin segmente

Nodurile arborelui vor avea 2 valori: indexul unic și valoarea propriu-zisă. Când spunem nodul a ne referim la nodul care are indexul egal cu a. Spre deosebire de reprezentarea clasică, reprezentarea prin segmente este mai compactă, motiv pentru care am păstrat mai multe informații. Principiul este urmatorul: pe primul nivel se află nodurile care au lungimea intervalului (dr-st+1) egală cu 1, pe al doilea nivel se află nodurile cu lungimea intervalului egală cu 2, ..., pe al k-lea nivel se află nodurile cu lungimea intervalului egală cu 2k-1. Definim astfel arborele de actualizare pe sufix:
Nodul y este părintele nodului x ⇔ y = x + (x&-x).

Este evident din reprezentare faptul că toate nodurile ce conțin poziția 3 se află de-asupra sa (pentru cei interesați de demonstrația matematică). Așadar, toți indecșii ce conțin poziția pos în interval vor fi termeni ai șirului (x)n, x0 = pos, xi+1 = xi + (xi&-xi), singura precizare fiind că oprim căutarea în momentul în care xi+1 depășește n, (echivalent cu xi+1 ≤ n). Numărul maxim de noduri pe care le vizităm pe drum este în cel mai rău caz log2n, făcând complexitatea funcției O(log n).

Implementarea în C++

În stânga este codul funcției în C++ care implementează simplu și eficient parcurgerea nodurilor cheie discutată mai sus. Am păstrat comentariul din buclă în scheletul funcției pentru claritate.



sau selectează-l manual:

void update(int ind, int val)
{
	for(int i=ind;i<=n;i+=(i&-i))
	{
		aib[i]+=val;
	}  
}

De ce O(log n)?

Fie șirul (x)n, x0 = pos, xi+1 = xi + (xi&-xi). Notăm xi = a1b ⇒ xi+1 = a1b + 01b = (a+1)0b ⇒ UB(xi+1) ≥ 1 + UB(xi). UB(h) ∈ [0, log2n] ∀h ∈ [1, n], deoarece n poate avea maxim log2n + 1 biți, dintre care un bit este setat, iar funcția logaritmică (în baza 2) este strict crescătoare. Fie k cel mai mare index pentru care xk ≤ n. Avem log2n ≥ UB(xk) ≥ 1 + UB(xk-1) ≥ 2 + ... ≥ k + UB(x0) ≥ 0 rezultă log2n - UB(x0) ≥ k, iar UB(x0) ∈ [0, log2n], de unde rezultă că valoarea maximă pe care o poate lua k este log2n.

Alte demonstrații🞃

Fie f:ℕ*→ℕ, f(x) = 2UB(x) = (x&-x); f(a1b) = 1b;
Fie șirul (x)n, x0 = pos, xi+1 = xi + f(xi)
Vom demonstra: Dacă k ∈ [x - f(x) + 1, x], atunci k ∈ [x + f(x) - f(f(x) + x) + 1, x + f(x)]
x < x + f(x) ⇔ 0 < f(x) ⇔ 0 < 2UB(x) adevărat (condiția 1)
f - f(x) + 1 ≥ x + f(x) - f(f(x) + x) + 1 ⇔ f(f(x) + x) ≥ 2 * f(x) ⇔ 2UB(f(x) + x) ≥ 2UB(x) + 1 ⇔ UB(x + f(x)) ≥ UB(x) + 1
Notăm forma binară a numărului x drept a1b
UB(x + f(x)) ≥ UB(x) + 1 ⇔ UB(a1b + 1b) ≥ 1 + 1b ⇔ (a + 1)0b ≥ 10b ⇔ (a+1) ≥ 1, adevărat (condiția 2)
(condiția 1) + (condiția 2) ⇒ Dacă k ∈ [x - f(x) + 1, x], atunci k ∈ [x + f(x) - f(f(x) + x) + 1, x + f(x)], c.c.t.d.
Din această relație rezultă prin inducție că toți termenii șirului (x)n conțin pos în intervalele lor.

Vom demonstra că ∄ k astfel încât k ⊄ (x)n, pos ∈ [k - f(k) + 1, k].
Presupunem prin absurd că ∃ k astfel încât k ⊄ (x)n, pos ∈ [k - f(k) + 1, k]. Fară a restrânge generalitatea putem afirma că k se află între 2 termeni consecutivi ai șirului xi și xi+1 ⇒ xi < k < xi+1 (condiție *)

Acestea sunt singurele 3 cazuri posibile astfel încât pos ∈ [k - f(k) + 1, k] și condiția * să fie îndeplinite. Putem reduce cazul II și III folosind faptul că din condiția * ⇒ f(k) ≤ f(xi), ceea ce vom demonstra mai jos.

Din h = M2UB(h) ∀h ∈ ℕ* ⇒ xi = M2UB(xi), iar UB(xi+1) ≥ 1 + UB(xi) ⇒ xi+1 = M2UB(xi) + 1 = M2UB(xi)
Din condiția * ⇒ k ∈ {xi + 1, xi + 2, ..., xi+1 - 1}, xi+1 = xi + 2UB(xi). Aplicând %2UB(xi) ⇒ k %2UB(xi) ∈ {1, 2, ..., 2UB(xi) - 1}. Așadar, UB(k) < UB(xi) ⇒ f(k) < f(xi) (condiția **). Notăm xi = a1b , k=A1B și |nr| = numărul de cifre a numărului nr, rezultă din condiția ** faptul că |B| < |b|, dar din condiția * ⇒ a1b < A1b ⇒ a1B < A1B ⇒ a < A ⇒ (a + 1) ≤ A ⇒ din condiția *: A1B < (a + 1)0b ≤ A0b ⇒ A1B < A0b ⇒ 1 ≤1B < 0b (b, B sunt șiruri de 0) ⇒ 1 < 0, contradicție ⇒ ∄ k astfel încât k ⊄ (x)n, pos ∈ [k - f(k) + 1, k].

Pe scurt: Aceste 2 demonstrații ne arată că singurii indecși ce trebuie actualizați sunt pos, pos + (pos&-pos), pos + (pos&-pos) + (pos + (pos&-pos)&-(pos + (pos&-pos))) s.a.m.d
