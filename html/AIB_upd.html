Functia de actualizare pe sufix

Daca dorim sa actualizam valoarea de pe pozitia pos, va trebuii sa actualizam toate nodurile din AIB care o contin. Amintim faptul ca nodul i contine suma subsecventei [i-(i&-i)+1,i] a vectorului, deci prin actualizarea elementului v[pos] vom actualiza de fapt fiecare nod i astfel incat
pos∈[i+1-(i&-i),i].Vom demonstra mai tarziu in articol faptul ca exista maxim log2n astfel de noduri, facand functia sa aiba complexitate de O(log2n).

Intrebarea ramane: cum putem identifica aceste pozitii?

Este greu de intuit logic motivul, dar prin aplicarea repetata a operatiei x=x+(x&-x) incepand cu x=pos putem atinge toate nodurile importante. Vom folosi drept reper vizualizarea arborelui indexat binar pentru a deduce formula folosita, dupa care ii vom demonstra validitatea matematic. Iata cateva exemple:

Pentru n=16 si pos=3 vom actualiza urmatoarele noduri:

AIB[3]=v[3]+val;
AIB[4]=v[3]+v[4]+val;
AIB[8]=v[1]+v[2]+v[3]+v[4]+v[5]+v[6]+v[7]+v[8]+val;
AIB[16]=v[1]+v[2]+v[3]+v[4]+v[5]+v[6]+v[7]+v[8]+v[9]+v[10]+v[11]+v[12]+v[13]+v[14]+v[15]+v[16]+val;

Pentru n=32 si pos=21 vom actualiza urmatoarele noduri:

AIB[21]=v[21]+val;
AIB[22]=v[21]+v[22]+val;
AIB[24]=v[21]+v[22]+v[23]+v[24]+val;
AIB[32]=v[1]+v[2]+...+v[21]+v[22]+...+v[32]+val;

Pentru n= si pos= vom actualiza AIB[398, 400, 416, 448, 512, 1024].

Reprezentarea grafica a unui AIB

In continuare puteti apasa pe reprezentarea AIB pe care o preferati:

Reprezentarea clasica

Nodurile arborelui vor avea 2 valori: indexul unic si valoarea propriu-zisa (AIB[index]) pe care o putem ignora cand reprezentam grafic. Cand spunem nodul a ne referim la nodul care are indexul egal cu a. Definim astfel arborele de actualizare pe sufix:
Nodul y este parintele nodului x <=> y=x+(x&-x) sau y=radacina.
*Radacina arborelui va fi nodul imaginar n+1, acesta nu ii corespunde unei subsecvente din vector si are doar rolul de a uni padurile disjuncte de arbori create prin ingorarea nodurilor cu index mai mare decat n.

Observam ca urcand arborele incepand cu nodul 3 pana la radacina parcurgem toate nodurile ce contin pozitia 3 in interval, iar asta este adevarat pentru orice pozitie datorita modului in care este definint parintele unui nod oarecare. Asadar, toti indecsii ce contin pozitia pos in interval vor fi termeni ai sirului (x)n, x0=pos, xi+1=xi+(xi&-xi), singura precizare fiind ca oprim cautarea in momentul in care xi+1 depaseste radacina, (echivalent cu xi+1<=n). Numarul maxim de noduri pe care le vizitam pe drum este in cel mai rau caz log2n, facand complexitatea functiei O(log2n).

Reprezentarea prin segmente

Nodurile arborelui vor avea 2 valori: indexul unic si valoarea propriu-zisa. Cand spunem nodul a ne referim la nodul care are indexul egal cu a. Spre deosebire de reprezentarea clasica, reprezentarea prin segmente este mai compacta, motiv pentru care am pastrat mai multe informatii. Principiul este urmatorul: pe primul nivel se afla nodurile care au lungimea intervalului (dr-st+1) egala cu 1, pe al doilea nivel se afla nodurile cu lungimea intervalului egala cu 2, ..., pe al k-lea nivel se afla nodurile cu lungimea intervalului egala cu 2k-1. Definim astfel arborele de actualizare pe sufix:
Nodul y este parintele nodului x <=> y=x+(x&-x).

Este evident din reprezentare faptul ca toate nodurile ce contin pozitia 3 se afla in nodurile alfate de-asupra sa (pentru cei interesati de demonstratia matematica). Asadar, toti indecsii ce contin pozitia pos in interval vor fi termeni ai sirului (x)n, x0=pos, xi+1=xi+(xi&-xi), singura precizare fiind ca oprim cautarea in momentul in care xi+1 depaseste n, (echivalent cu xi+1<=n). Numarul maxim de noduri pe care le vizitam pe drum este in cel mai rau caz log2n, facand complexitatea functiei O(log2n).

De ce O(log2 n)?

Fie sirul (x)n, x0=pos, xi+1=xi+(xi&-xi). Notam xi=a1b => xi+1=a1b+01b=(a+1)0b => UB(xi+1)>=1+UB(xi). UB(h)∈[0,log2n] ∀h∈[1,n] ,deoarece n poate avea maxim log2n + 1 biti, dintre care un bit este setat, iar functia logaritmica (in baza 2) este strict crescatoate. Fie k cel mai mare index pentru care xk<=n. Avem log2n>=UB(xk)>=1+UB(xk-1)>=2+...>=k+UB(x0)>=0 rezulta log2n-UB(x0)>=k, iar UB(x0)∈[0,log2n], de unde rezulta faptul ca valoarea maxima pe care o poate lua k este log2n.

Alte demonstratii🞃

Fie f:ℕ*→ℕ, f(x)=2UB(x)=(x&-x); f(a1b)=1b;
Fie sirul (x)n, x0=pos, xi+1=xi+f(xi)
Vom demonstra: Daca k∈[x-f(x)+1,x] atunci k∈[x+f(x)-f(f(x)+x),x+f(x)]
x<x+f(x) <=> 0<f(x) <=> 0<2UB(x) adevarat (conditia 1)
f-f(x)+1>=x+f(x)-f(f(x)+x)+1 <=> f(f(x)+x)>=2*f(x) <=> 2UB(f(x)+x)>=2UB(x)+1 <=> UB(x+f(x))>=UB(x)+1
Notam forma binara a numarului x drept a1b
UB(x+f(x))>=UB(x)+1 <=> UB(a1b+1b)>=1+1b <=> (a+1)0b>=10b <=> (a+1)>=1 adevarat (conditia 2)
(conditia 1) + (conditia 2) => k∈[x-f(x)+1,x] atunci k∈[x+f(x)-f(f(x)+x),x+f(x)] cctd.
Din aceasta relatie rezulta prin inductie faptul ca toti termenii sirului (x)n contin pos in intervalele lor.

Vom demonstra ca ∄ k astfel incat k⊄(x)n, pos∈[k-f(k)+1,k].
Presupunem prin absurd ca ∃ k astfe incat k⊄(x)n, pos∈[k-f(k)+1,k]. Fara a restrange generalitatea putem afirma faptul ca k se afla intre 2 termeni consecutivi ai sirului xi si xi+1 => xi< k <xi+1 (conditie *)

Acestea sunt singurele 3 cazuri posibile astfel incat pos∈[k-f(k)+1,k] si conditia * sa fie indeplinite. Putem reduce cazul II si III folosind faptul ca din conditia * => f(k)<=f(xi), ceea ce vom demonstra mai jos.

Din h = M2UB(h),∀h∈ℕ* => xi=M2UB(xi), iar UB(xi+1)>=1+UB(xi) => xi+1=M2UB(xi)+1=M2UB(xi)
Din conditia * => k∈{xi+1,xi+2,...,xi+1-1}, xi+1=xi+2UB(xi). Aplicand %2UB(xi) => k%2UB(xi)∈{1,2,...2UB(xi)-1}. Asadar, UB(k)<UB(xi)=>f(k)<f(xi) (conditia **). Notam xi=a1b ,k=A1B si |nr|=numarul de cifre a numarului nr, rezulta din conditia ** faptul ca |B|<|b|, dar din conditia * => a1b<A1b => a1B<A1B => a<A => (a+1)<=A => din conditia *: A1B<(a+1)0b<=A0b => A1B<A0b => 1<=1B<0b (b,B sunt siruri de 0) => 1<0 contradictie => ∄ k astfel incat k⊄(x)n, pos∈[k-f(k)+1,k].
