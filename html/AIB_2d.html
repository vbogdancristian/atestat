Generalizarea în 2 dimensiuni

Conceptul de arbore indexat binar îl putem generaliza pentru tablouri multi-dimensionale. Pentru AIB 2d vom avea următoarea problemă de rezolvat:
Se dă o matrice a (indexată de la 1,1) cu n linii și m coloane, după care se dau k operații care pot fi de 2 tipuri:
A) Adaugă val la a[posX][posX]; (Actualizare)
B) Afișează suma elementelor din matrice din dreptunghiul cu colțurile în [1,1] și [posX,posY]; (Interogare)

Complexitatea dorită este O(k*log n * log m), adică O(log n * log m) pentru fiecare operație.

Noua structură

Tot ce am invățat despre AIB se aplică și aici, dacă în mod normal AIB[x] = Σ(x-(x&-x)+1,x), atunci pentru 2 dimensiuni AIB[x][y] = Σ[(x-(x&-x)+1,y-(y&-y)+1),(x,y)]. Iată câteva exemple:

AIB[3][6] = Σ[(3,5),(3,6)] = a[3][5] + a[3][6];
AIB[1][4] = Σ[(1,1),(1,4)] = a[1][1] + a[1][2] + a[1][3] + a[1][4];
AIB[2][6] = Σ[(1,5),(2,6)] = a[1][5] + a[1][6] + a[2][5] + a[2][6];
AIB[10][20] = Σ[(9,17),(10,20)] = a[9][17] + a[9][18] + a[9][19] + a[9][20] + a[10][17] + a[10][18] + a[10][19] + a[10][20];

Reprezentarea grafică a unui AIB 2d este greu de urmărit, dar ideea din spate este simplă: AIB-ul bidimensional este un AIB care are drept noduri alte AIB-uri. Așadar, nodul x nu va mai avea valoare propriu-zisă, ci un AIB propriu-zis (evident, acest AIB este 1-dimensional).

*Dimensiunea AIB-ului din prima poză este 16x16, iar în a doua poză este 32x8;

*Nu am ilustrat arborele de sufix, dar reprezentarea sa este similară cu vizualizarea arborelui prefix;

Noile funcții

Funcțiile de actualizare și interogare 2-dimensionale sunt extensii logice a celor clasice.

Noua funcție de actualizare pe sufix

Având ca input o valoare val și două poziții posX și posY, vom actualiza toate nodurile din toate AIB-urile ce contin a[posX][posY]. Aplicăm aceeași operație repetată x=x+(x&-x) pentru ambii indecși de data aceasta, creând șirurile (x)n și (y)n. Vom adăuga val la AIB[xi][yj] pentru oricare i,j astfel încât xi≤n si yj≤m. Am dedus în articolul funcției clasice de actualizare că există maxim log n (respectiv log m) indecși ce respectă condiția, așadar complexitatea finală a noii funcții este O(log n * log m).

Noua funcție de interogare pe prefix

Vrem să aflăm suma din dreptunghiul [(1, 1) , (posX, posY)], unde posX și posY sunt indecși dați. Aplicăm aceeași operație repetată pentru ambii indecși de data aceasta, creând sirurile (x)n și (y)n. Vom culege valoarea din fiecare nod AIB[xi][yj] pentru oricare i,j astfel încât xi>0 și yi>0. Am dedus în articolul funcției de interogare că există log n (respectiv log m) indecăi ce respectă condiția, așadar complexitatea finală a noii funcții este O(log n * log m).



Testează: Σ[(1,1), ( , )] = Σ[(1,1),([11011],[10100]) = AIB[27][20] + AIB[27][16] + AIB[26][20] + AIB[26][16] + AIB[24][20] + AIB[24][16] + AIB[16][20] + AIB[16][16];

Implementarea în C++


După cum puteți vedea, codul este același, dar vom mai adăuga o bucla înauntru. Ambele operatii sunt realizate in O(log n * log m), buclele fiind maxim log n respectiv log m.


sau selectează-l manual:

void update(int indX, int indY, int val)
{
	for(int x=indX;x<=n;x+=(x&-x))
	{
		for(int y=indY;y<=m;y+=(y&-y))
		{
			aib[x][y]+=val;
		}
	}
}
int query(int indX, int indY)
{
	int sum=0;
	for(int x=indX;x>0;x-=(-x&x))
	{
		for(int y=indY;y>0;y-=(-y&y))
		{
			sum+=aib[x][y];
		}
	}
	return sum;
}
Un aspect important la AIB este faptul că, spre deosebire de alte structuri de date, pot fi generalizați cu ușurință pe dimensiuni mai mari. Dacă avem nevoie de un AIB 3d, singurul lucru ce trebuie adăugat în interiorul funcțiilor este înca o bucla for identică cu celelalte 2.
