Arbori indexați binari și Arbori de intervale

Până acum am văzut cum funcționează arborii indexați binari pentru stocarea unei sume, dar pentru ce alte operații i-am putea aplica? Ei bine, dacă vrem să folosim un singur AIB atunci trebuie ca funcția să fie inversabilă. Atunci când spunem că Σ(st,dr) = Σ(1,dr) - Σ(1,st-1) ne folosim de faptul că primele st-1 elemente se reduc, am putea scrie în mod asemănător ∏(st,dr) = ∏(1,dr) / ∏(1,st-1) (pentru numere nenule) sau ⊕(st,dr) = ⊕(1,dr) ^ ⊕(1,st-1) (a ^ a = 0, a ^ 0 = a, operație asociativă, deci funcția inversă lui xor este ea însăși). NU putem folosi un singur AIB pentru a determina minimul, maximul, cel mai mare divizor comun etc, cel mult putem determina răspunsul la interogari de tip f(st = x - (x&-x) + 1, dr = x]. Pentru acest tip de probleme este folosită altă structură de date care poate actualiza și interoga cu aceeași complexitate ca cea studiată, numită arbori de intervale (AInt pe scurt).

Toate problemele ce pot fi rezolvate prin AIB pot fi rezolvate și prin AInt, dar reciproca nu se aplică. Dacă modificăm problema originală astfel încât în loc de sumă să calculăm minimul/maximul pe o secvență atunci nu vom reuși cu un singur AIB. Dacă nu vrem să folosim AInt se pune următoarea întrebare: Oare am putea rezolva problema cu două AIB-uri? Da, în O(m log n log n) / O(m log n) amortizat.

AIB de minim/maxim

Vrem să folosim AIB pentru a rezolva problema specifică arborilor de intervale:

A) Actualizare pe o singură poziție în O(log2 n)/O(log n) amortizat
B) Interogarea maximului din secvența [st,dr] în O(log n)

Vom avea un AIB care actualizează pe sufix, interoghează pe sufix, notat AIB1 și un alt AIB care actualizează pe prefix, interoghează pe sufix, notat AIB2. AIB1[x] va stoca max[x - (x&-x) + 1, x], iar AIB2[x] va stoca max[x, x + (x&-x) + 1] (secvența oglindită). De asemenea păstrăm vectorul original.

Funcția de interogare

Pentru a determina maximul dintr-o secvența [st,dr] vom interoga ambele structuri de date în intervalul [st,dr] (va avea mai mult sens după ce vedeți codul) și vom returna maximul dintre cele 2. Problema este că aceste 2 parcurgeri se apropie, dar nu ating un singur index din [st,dr], deci vom mai face o verificare la final. Acesta este codul:

int QUERY(int st, int dr)
{
    int val=-1;
    for(int i=dr;i-(i&-i)>=st;i-=(i&-i))
    {
        val=max(val,aib1[i]);
    }
    int i=st;
    for(;i+(i&-i)<=dr;i+=(i&-i))
    {
        val=max(val,aib2[i]);
    }
    val=max(val,v[i]);
    return val;
}

Funcția de actualizare

Este dificil de implementat din cauza faptului că setăm valoarea unei poziții, nu o înlocuim cu maximul dintre cea veche și inputul nou. Astfel, va trebui să ștergem orice semn că a existat vreodată valoarea respectivă. Vom compara valoarea veche a nodurilor cu cea nouă, iar dacă aceasta este mai mare putem înlocui fără grijă, urcând către rădăcină. Dacă în schimb aceasta nu este mai mare, apare o problemă, căci nu putem lăsa valoarea pe care vrem să o înlocuim, deci trebuie scanat fiecare fiu (frate dacă ne gândim la reprezentarea prin segmente) și îi vom lua valoarea maximă. Complexitatea devine O(log2 n), dar pentru mai multe apeluri de funcție cu parametri aleatorii devine O(log n) amortizat. Acesta este codul:

void UPDATE(int pos, int val)
{
    int oldValue=v[pos];
    v[pos]=val;
    int copyval=val;
    int node=pos;
    ///aib1
    while (node<=n)
    {
        if (val<aib1[node])
        {
            if(oldValue==aib1[node])
            {
                val=max(val,v[node]);
                for(int i=0;i<__builtin_ctz(node);i++)///functia __builtin_ctz(x) returneaza UB(x), este mai rapid si mai sigur decat log2(x&-x)
                {
                    int child=node-(1<<i);
                    val=max(val,aib1[child]);
                }
            }
            else break;
        }
        if (val==aib1[node]) break;
        aib1[node]=val;
        node+=(node&-node);
    }
    ///aib2
    node=pos;
    val=copyval;
    while (node>0)
    {
        if (val<aib2[node])
        {
            if(oldValue==aib2[node])
            {
                val=max(val,v[node]);
                for(int i=0;i<__builtin_ctz(node);i++)
                {
                    int child=node+(1<<i);
                    val=max(val,aib2[child]);
                }
            }
            else break;
        }
        if (val==aib2[node]) break;
        aib2[node]=val;
        node-=(node&-node);
    }

}
Cu toate că soluția nu este O((n+m)log n) curat, e de 2 ori mai rapidă decât implementarea obișnuită cu arbori de intervale. Codul ar deveni mai eficient (ca timp și ca linii de cod) dacă problema originală nu ar fi setat un element, ci ar fi făcut maximul dintre el și poziția deja-existentă. În acest caz am fi putut face pentru ambele AIB-uri o actualizare simplă, ceea ce ar fi dus la O(log n) complexitate.

Ce înseamnă asta?

Nimic semnificativ, tot arborii de intervale vor fi folosiți pentru probleme de minim/maxim și actualizări pe interval, tot arborii indexați binari se vor prefera pentru probleme cu funcții inversabile. Scopul articolului este de a vedea cât de tare poate fi împinsă această structură de date peste limita sa.
