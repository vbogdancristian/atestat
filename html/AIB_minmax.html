Arbori indexati binari si Arbore de intervale

Pana acum am vazut cum functioneaza arborii indexati binari pentru stocarea unei sume, dar pentru ce alte operatii i-am putea aplica? Ei bine, daca vrem sa folosim un singur AIB atunci trebuie ca functia sa fie inversabila. Atunci cand spunem ca Σ(st,dr)=Σ(1,dr)-Σ(1,st-1) ne folosim de faptul ca primele st-1 elemente se reduc, am putea scrie in mod asemanator ∏(st,dr)=∏(1,dr)/∏(1,st-1) sau ⊕(st,dr)=⊕(1,dr)^⊕(1,st-1) (deoarece a^a=0, a^0=a, facand functia inversa lui xor ea insasi). NU putem folosi un singur AIB pentru a determina minimul, maximul, cel mai mare divizor comun etc, cel mult putem determina raspunsul la interogari de tip f[x-(x&-x)+1,x]. Pentru acest tip de probleme este folosita alta structura de date care poate actualiza si interoga cu aceeasi complexitate ca cea studiata, numita arbori de intervale (Aint pe scurt).

Toate problemele ce pot fi rezolvate prin AIB pot fi rezolvate si prin AInt, dar reciproca nu se aplica. Daca modificam problema originala astfel incat in loc de suma sa calculam minimul/maximul pe o secventa atunci nu vom reusi cu un singur AIB. Daca nu vrem sa folosim AInt se pune urmatoarea intrebare: Oare am putea rezolva problema cu doua AIB-uri? Da, in O(m log n log n).

AIB de minim/maxim

Vrem sa folosim AIB pentru a rezolva problema specifica arborilor de intervale:

A) Actualizare pe o singura pozitie in O(log2 n)/O(log n) amortizat
B) Interogarea maximului din secventa [st,dr] in O(log n)

Vom avea un AIB care actualizeaza pe sufix, interogheaza pe sufix, notat AIB1 si un alt AIB care actualizeaza pe prefix, interogheaza pe sufix, notat AIB2. AIB1[x] va stoca max[x-(x&-x)+1,x], iar AIB2[x] va stoca max[x,x+(x&-x)+1] (secventa oglindita). De asemenea pastram vectorul original.

Functia de interogare

Pentru a determina maxim dintr-o secventa [st,dr] vom interoga ambele structuri de date in intervalul [st,dr] (veti vedea la ce ma refer cand vedeti codul) si vom returna maximul dintre cele 2. Problema este ca aceste 2 parcurgeri se apropie dar nu ating un singur index din [st,dr], deci vom mai face o verificare la final. Acesta este codul:

int QUERY(int st, int dr)
{
    int val=-1;
    for(int i=dr;i-(i&-i)>=st;i-=(i&-i))
    {
        val=max(val,aib1[i]);
    }
    int i=st;
    for(;i+(i&-i)<=dr;i+=(i&-i))
    {
        val=max(val,aib2[i]);
    }
    val=max(val,v[i]);
    return val;
}

Functia de actualizare

Este dificil de implementat din cauza faptului ca setam valoarea unei pozitii, nu o inlocuim cu maximul dintre cea veche si inputul nou. Astfel va trebui sa stergem orice semn ca a existat vreodata valoarea respectiva. Va trebui sa comparam valoarea veche a nodurilor cu cea noua, iar daca aceasta este mai mare putem inlocui fara grija, urcand catre radacina. Daca in schimb aceasta nu este mai mare apare o problema, caci nu putem lasa valoarea pe care vrem sa o inlocuim, deci vom scana fiecare fiu (frate daca ne gandim la reprezentarea prin segmente) si ii vom lua valoarea maxima. Complexitatea devine O(log2 n), dar pentru mai multe apeluri de functie cu indecsi diferiti devine O(log n) amortizat. Acesta este codul:

void UPDATE(int pos, int val)
{
    int oldValue=v[pos];
    v[pos]=val;
    int copyval=val;
    int node=pos;
    ///aib1
    while (node<=n)
    {
        if (val<aib1[node])
        {
            if(oldValue==aib1[node])
            {
                val=max(val,v[node]);
                for(int i=0;i<__builtin_ctz(node);i++)///functia __builtin_ctz(x) returneaza UB(x), este mai rapid si mai sigur decat log2(x&-x)
                {
                    int child=node-(1<<i);
                    val=max(val,aib1[child]);
                }
            }
            else break;
        }
        if (val==aib1[node]) break;
        aib1[node]=val;
        node+=(node&-node);
    }
    ///aib2
    node=pos;
    val=copyval;
    while (node>0)
    {
        if (val<aib2[node])
        {
            if(oldValue==aib2[node])
            {
                val=max(val,v[node]);
                for(int i=0;i<__builtin_ctz(node);i++)
                {
                    int child=node+(1<<i);
                    val=max(val,aib2[child]);
                }
            }
            else break;
        }
        if (val==aib2[node]) break;
        aib2[node]=val;
        node-=(node&-node);
    }

}
Cu toate ca solutia nu este O((n+m)log n) curat, este de 2 ori mai rapida decat implementarea obisnuita cu arbori de intervale. Codul ar deveni mai eficient (ca timp si ca linii de cod) daca problema originala nu ar fi setat un element, ci ar fi facut maximul dintre el si pozitia deja-existenta.

Ce inseamna asta?

Nimic, tot arborii de intervale vor fi folositi pentru probleme de minim si maxim si actualizari pe un interval, tot arborii indexati binari se vor prefera pentru probleme cu functii inversabile (adunare/inmultire/xor). Scopul articolului este de a vedea cat de tare poate fi impinsa aceasta structura de date peste limita sa.
